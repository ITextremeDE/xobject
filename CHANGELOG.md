# Changelog

All notable changes to xObject will be documented in this file.

The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/). Software releases will use [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

The project is in early development. No software release is available yet.

### Added
- Consistent standard-only initial object-list columns, retained account/view-scoped browser column choices, creation-time sorting, localized object navigation and clear filtered-empty states.
- Regional numeric record inputs with exact canonical request values, field-level precision/range/currency feedback and blocked invalid saves; wider responsive field editors.
- Compact instance Journal table with selectable context/value columns and structured detail dialogs; collapsible custom relationship tables, maximum-one hints and module-aware Primary help/preparation.
- Fresh development-database guidance separates schema initialization, Administrator provisioning and demo seeding, with semantic system-column groups, schema-equivalence checks and recoverable database switching.
- Versioned Primary-level bindings by object UUID for Address → Project → Case, with preflight, lifecycle protection, shared API/MCP context and role-filtered candidates. Record forms show inherited single-value fields and persist only the direct association; Workspace General configures the levels.
- Generic relationship endpoint conditions reuse single-choice field rules in configuration, candidate pagination and final-state writes. The Contact fixture restricts Organization/Contact-person links and provides an AP/Individual-contact Identities list without another object type. Controller dependencies and atomic journals remain protected.
- Record-page UI refinement: clearer object/title navigation, a centered two-column form and a sticky Save/Create/Reset bar with missing-field/draft feedback. New records explain later tabs; formatted previews and inactive fields expand on demand. Empty choices and Journal change filters use clearer labels, while tables retain their shared full-width presentation.
- Record relationships keep the Primary chain separate and show one table per applicable custom relationship, including single-target definitions. A top-level Link with… action edits General links; General and subordinate Primary links stay in the Dossier without duplicate Details tables. Aligned page edges, compact header and horizontally wrapped Category choices reduce visual clutter; a staged selection dialog retains unsaved changes. Native single selection, multiple choices across pages, server-side object filtering, Selected view, guarded dismissal and navigation preserve record drafts; inactive/read-only connections stay readable.
- Dossier object-type filter combines with search/sort before pagination; shared table cells consistently suppress hover underlines for links and buttons.
- Dossier now uses the shared record data table with relationship type, object type, Keyword, Type, Status and Category; complete-dossier search/sort, column/page selection, actions and pagination match other record lists. Current endpoint classifications include retained choices; absent standard fields stay empty. Record and edge identities remain separate, and journal snapshots are unchanged.
- Record Journal now reuses the shared data table, column/page selection, actions and pagination, with readable before/after previews, responsive column defaults and keyboard-accessible detail dialogs. Filters and audit metadata remain above the table; chronological server order and historical formatting are preserved.
- Record Journal with server-side field/change-kind filters, pagination; before/after values use historical field kinds/configuration and relationship events retain their edge identity. Unsaved drafts stay visible across all record tabs. Relationship search/selection uses a dedicated picker; empty optional fields stay compact.
- Conditional custom-field applicability configured in the shared field editor by stable single-choice field/option identities, with common API/MCP final-state validation, conditional requiredness, dependency protection and atomic journals. Fictional Contacts now show person fields and Commercial register only for their applicable contact kinds; incompatible changes preserve existing values.
- Relationship definition forms start with the object pair/direction and reveal side settings once both objects are selected. Symmetric undirected relationships use one shared name/cardinality; separate side drafts survive mode/object changes. Identity is grouped separately and side descriptions use the selected object names. Object selection is alphabetical; technical-name inputs share associated format/fixed-name help across definition forms.
- Database safeguards: numbered migration history, deferred row/registry integrity, restricted runtime database credentials, shared readers/workspace write barriers, targeted relationship checks and chronological/pagination indexes. Definition edits require draft versions; protected module fields retain structural protection while allowing intended input aids.
- Read-only relationship tree rooted at the opened record, with real inherited Primary context, lazy paginated branches, labeled cross references and path-based cycle termination. Shared API/MCP reads preserve rights and storage; keyboard navigation, record links and explicit depth/context limits keep the tree usable.
- Record relationships with workspace-scoped endpoint identities, atomic API/MCP field replacements, version checks, explicit rule activation/preflight, final-state cardinalities and Primary cycle prevention. Record forms show a single selection or a paginated list per side; a Dossier tab and shared endpoint journal events expose the same connections. The fictional demo seed now creates its 45 planned links.
- Workspace relationship-type definitions with protected Primary/General system meanings, configurable own directed/undirected types, translated side names, per-side cardinalities and allowed object pairs. Shared API/MCP authorization, versions, composite workspace foreign keys and atomic property journals back the responsive settings editor. Custom rules begin as drafts and activate after preflight. Minimal Projects activation supplies global Primary association with configured parent levels; General is always available. CRM provisioning, full module templates and ownership adoption remain future work.
- Explicit fictional development seed with five related test domains, 54 initial records, typed fields and 45 actual relationships; existing data is never overwritten by the seed command.
- Stage optional standard fields in their existing editors before creation. API/MCP can install Keyword requiredness or versioned Type/Status/Category configuration atomically, including storage and journal rollback on validation failure.

General is always available; workspace Projects activation controls global Primary association for current/future child types; configured role bindings constrain parents. Versioned shared API/MCP operations, immediate workspace settings and a preservation-checked migration retain existing links/history.
- Open record creation/editing on dedicated responsive pages using one form, with grouped fields, top-level actions, separate technical metadata and a formatted Journal tab. Preserve drafts across tabs, common validation/authorization, keyboard save and originating list/Dashboard filters and focus; a future quick-edit Sheet can reuse the form.
- Unify definition and instance journals with structured event cards, labeled context, framed before/after values, integrated technical disclosures and readable localized properties. Current field/object names and record Keywords supplement immutable events; instance filters remain server-side and Administrator-only.
- Reorganize settings and nested editors with grouped localization, concrete inherited-format examples, tabbed workspace design controls, adjacent light/dark previews and effective theme-color swatches. User, group, membership, session and field lists share searchable or paginated layouts as applicable, semantic counts and readable mobile rows; immediate membership changes are explicitly identified.
- Clarify object/field administration with scoped property actions, separate availability/history and framed technical details, grouped editors and direct Type/Status wording. Sort fields alphabetically with stable technical-name/identity tie-breakers, distinguish duplicate mobile labels and retain inactive/deleted indicators. All required-field controls consistently use Yes/No; the table remains read-only.
- Align Dashboard summary cards and activity-chart presentation with dashboard-01: responsive numeric typography, two-line card footers, wide-screen period toggles/mobile Select, reference chart spacing and a standard dotted tooltip. Keep existing metrics, regional formatting and independent overlapping activity series.
- Dashboard and individual record lists share a responsive toolbar with search on the left, compact column/action buttons on the right and an unchanged common pagination footer. Object-list headings stay separate; Dashboard object filters remain above the toolbar.
- Rename the Dashboard action to Add filter and give shared record-action menus enough room for single-line labels, consistent icons and a separate copy-ID group.
- Muted table headers and example-aligned user-menu profile spacing; resource links sit above the separate sidebar user footer.

- Settings use the shadcn Sidebar 13 dialog layout, with Personal sections for Appearance and Language & region, plus Workspace sections for General (editable name, read-only code), Language & region (default language), and Object types (alphabetical standard shadcn Select, editable translated labels, read-only technical names, classification configuration and a field-definition table). Workspace name changes share API/MCP validation and atomic journaling. Save/Reset apply to the current page; the close guard covers all unsaved drafts.
