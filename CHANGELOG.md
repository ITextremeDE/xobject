# Changelog

All notable changes to xObject are documented here, using [Keep a Changelog](https://keepachangelog.com/en/1.1.0/). Software releases will use [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

The project is in early development. These entries describe source changes, including locally verified work that has not yet been published. No installable software release is available. Planned capabilities are identified as specifications rather than delivered functionality. Related changes within this unreleased baseline are consolidated to describe their final behavior; superseded intermediate UI states are not separate release features.

### Added

- Record-header “Link with…” and “New linked record” object dropdowns: General-only direct actions, submenus using existing relationship side labels, an object-filtered existing-record picker and atomic linked creation through API/MCP. New records retain source context, inverse-side selection and guarded source return; versions, rights, conditions and cardinalities are enforced without replacing existing source links.
- Initial object/field content permissions for users and groups, additive active-group grants and explicit user overrides. Sensitive types provide protected Access principals with creator defaults and optional workspace-public records. Actor-bound API/MCP checks cover records, fields, search/counts, Dashboard, relationships, Primary tree/context and historical journal projections. Migration 8 retains existing data without automatic grants; the expanded ownership/foreign-access model remains a specification.
- Database-backed Modules settings with Contacts & Relations, Projects & Tasks and Documents & Communication. Projects activation supplies protected base Contacts/Projects/Cases/Tasks and fixed Contact → Project → Case UUID roles; planned modules remain visible. Reserved module object technical names apply even while modules are disabled/planned, and collisions never silently adopt custom definitions. Complete domain templates/shared-module ownership remain open.
- Form designer for actual workspace objects, with translated editable groups, scalar/relationship placement and ordering, half/full widths, optional relationship visibility and initial table state. New objects start with General; added elements remain Unassigned, including after group deletion. Versions, required-element guards, retained inactive entries and migrations preserve authored layouts and stored values. Module-specific metadata is retained without speculative UI views.
- Shared record and workspace tables with standard-only initial columns, account/view-scoped column visibility, current-page selection, supported server sorting/filtering, row actions and complete pagination. Dashboard combines the normal mixed-object table with exploratory real statistics/activity, shadcn dashboard-01 cards/gradients and a zone-aware 7/30/90-day chart. Growing management tables reuse the footer and muted headers.
- Read-only Projects-owned Primary hierarchy tree with inherited ancestor context, lazy paginated descendants, keyboard navigation, defensive cycle termination and explicit depth/context limits. General/custom connections remain in the Dossier.
- Relationship types with one object pair per custom definition, directed/undirected semantics, translated side labels, one conventional cardinality and separate required-link settings. Shared API/MCP validates composite workspace identities, protected system meanings, used pair/direction locks, activation preflight and atomic per-property journals. General stays core; Projects gates Primary association.
- Record-edge storage and identity registry with atomic scalar/relationship replacement, optimistic endpoint/definition versions, final-state cardinalities, Primary uniqueness/cycles and one central edge journal event projected to both endpoints.
- Generic field and relationship-endpoint applicability using stable unconditional single-choice controller/option UUIDs. Final-state validation, conditional requiredness and dependency protection retain incompatible data until explicitly cleared. The fictional Contact configuration supports one Organization per Contact person and direct symmetric Identities lists without another object type or name-based behavior.
- Full-width dedicated record creation/edit pages with one grouped form, sticky Save/Create/Reset actions, missing-field feedback, retained drafts across tabs and formatted previews/inactive-value disclosures. Created/changed metadata appears above Journal; technical details retain identities/version. Custom single-target connections use labeled InputGroups; multi-target sides use individual collapsible tables. General and subordinate Primary links are not duplicated in Details.
- Dossier data table with relationship type, object type, Keyword, Type, Status and Category; object filtering, localized search/sort, columns, page selection/actions and pagination. Record/definition/instance Journals share tables and structured detail dialogs, preserving immutable snapshots, current-name context, historical type formatting and the appropriate server/client pagination contract.
- Numbered local migrations, deferred business-row/registry integrity, definition versions, restricted runtime versus operator credentials, schema/workspace lock barriers, targeted graph checks and pagination/history indexes. Fresh-database guidance separates initialization, Administrator provisioning and optional seeding; recoverable cutover retains backups and prior databases.
- Explicit fictional five-domain development seed with 54 initial records, typed fields and 45 actual relationships through normal application operations. Seeding refuses existing workspaces; manually provisioned local inventory/test accounts are separate fixtures, not installation defaults.
- Administrator user management with start-password provisioning, mandatory first password change, optimistic edits, reversible activation and session revocation. Secret-free user/security journals are atomic; Workspace General shows creator and evidenced creation time. Instance Journal exposes recorded events with scope/property/entity-kind filtering.
- Workspace-scoped User/Designer roles and direct user groups with versioned membership/activation journals. Administrators manage roles/memberships and content grants; Designers configure permitted workspace definitions and input aids. Removing workspace access revokes direct memberships/grants without deleting accounts or history.
- Workspace language catalog/policy for shipped German/English packs, independent definition languages, retained unavailable preferences/translations, versioned API/MCP configuration and transactional journals. A shared translation input switches languages without losing draft labels.
- Named workspace time zones, optional personal overrides and regional display preferences independent of UI language. Exact numeric/money strings, date-only values, currency placement, first weekday, DST-gap rejection and explicit overlap selection are shared across record inputs, tables and journals.
- Shared workspace shadcn appearance: base/accent/chart palettes, primary/secondary overrides, radii, interface/heading fonts from the pinned 26-font catalog, menu surfaces/accents and interactive light/dark previews. Fonts/licenses are served locally; saved tokens cover portals and switching workspaces. Browser light/dark/system preference remains personal.
- Personal Profile, Account & security, Appearance and Language & region settings: own display-name changes, read-only sign-in email, verified password changes, own-session inspection/revocation, bounded failed-password guard and secret-free atomic journals. Avatar initials/disabled upload preparation does not enable image storage or email changes.
- Definition deactivation/reactivation and confirmed deletion only when unused, with dependency/current/history checks, protected supplied definitions, tombstones and atomic journals. Type/Status lifecycle is coupled; inactive content remains inspectable. Record recycle-bin/permanent-deletion operations remain pending.
- Optional Keyword, Type/Status and Category installation through their shared editors and API/MCP, including required flags, stable localized choices/defaults, Without Type statuses, manual option ordering and single/multiple Category selection. Staged configuration and storage creation commit together; absent fields remain absent across migrations and missing Keyword uses the UUID.
- Unified custom-field editor for Text, Multiline/Markdown, Integer, Decimal, Money, Boolean, Date, Date/time, choices, Email, international Telephone, URL and User/Group references. Requiredness, precise validation and lossless conversion preflight apply through all channels; conversion journals preserve original history.
- React/Vite frontend, shared TypeScript contracts and direct workspace/list/record/settings routes, URL search/sort/page state, guarded navigation, centralized keyboard shortcuts/help and scrollable Command/Ctrl+K navigation with authorized record search. Sidebar resources link to planned documentation/changelog/roadmap destinations above the user menu.
- Fastify/Kysely/PostgreSQL/Better Auth local backend with UUIDv7 identities, readable workspace-prefixed tables, localized definition labels, explicit migration/provisioning commands, per-field journals, isolated PostgreSQL/web tests and GitHub application checks.
- Independent public Astro project introduction with Tailwind, ITextreme semantic tokens, selected Base UI shadcn primitives, self-hosted fonts, unchanged official brand assets, light/dark/system menus, validated MDX, metadata/sitemap and responsive/CSP browser checks. Full Starlight docs and product installation remain planned.
- Product PRD with 47 stable requirement IDs and acceptance scenarios, ADRs, public roadmap, shared agent instructions and the full `AGPL-3.0-only` declaration/license including Premium code.

### Changed

- Reconciled the complete documentation against source and accepted product decisions: linked ADR refinements, removed obsolete current-state assertions, consolidated development/verification guidance and release entries, and distinguished local implementation, target behavior and release/publication boundaries.
- Specified the standalone xObject permission target: graded ownership/activity involvement, bounded foreign/group inheritance, creation capability, record-level field restrictions, public/private precedence, confidentiality, calendar visibility, notification recipients and access-preserving migration. This does not implement the new resolver or deferred calendar/notification services.
- Permission administration explains effective user/group sources, separates principal lists from grants, exposes direct selection actions and keeps Save/Reset in the fixed footer. Object labels and sensitivity save atomically with both expected versions; member removal explains grant/membership effects before confirmation.
- Settings and nested editors use the Sidebar 13 background hierarchy and consistent rounded functional sections, spacing, responsive tables and fixed action placement. Record groups/loading states reuse these sections and full main-content width. Personal/workspace/instance navigation shares one ordered definition; email belongs to Account & security.
- Object/field administration separates properties, alphabetical fields, lifecycle/history and framed technical details. Consistent Yes/No requiredness, shared translation controls, staged optional standards and side-by-side Type/Status input aids retain Save/Reset and dependency protection.
- Relationship editors start with object pair/direction, then identity and applicable side controls. Symmetric sides share controls; independent drafts survive mode changes. Fixed values use read-only presentation, and technical-name controls share format/fixed-name help. New definitions clearly start as drafts.
- Record/table menus use consistent icons, spacing and copy-ID grouping; Dashboard “Add filter” adds object-filter tabs. User-menu/resource spacing, toolbar alignment, responsive period selection and gradient chart presentation follow the selected shadcn examples while retaining actual authorized data.
- Common dialog actions use Cancel/Create for creation, Close/Reset/Save for editing and explicit destructive confirmations. Reset supports invalid drafts; normal dialogs have localized close buttons and all close paths preserve pending/dirty guards.
- Standard-field names/technical names are reserved even when absent; unused Type/Status options can be deleted only without current/history references or retained child mappings. Deleted identities are never reused. Administrator status uses the protected `sys_users.is_admin` flag, preserving earlier assignments.
- Public website header/footer use the shared ITextreme structure, neutral theme/mobile icon menus, semantic surfaces, compact navigation, nine social icons and actual stack/developer credit, retaining CSP and asset notices.

### Removed

### Fixed

- Typed SQL-count results in linked-record tests so the full server/root type check includes those assertions without unknown-row errors; the complete application tests and builds pass.
- Exact regional numeric/date/time editing preserves semantic values across load/blur and preference changes. Invalid drafts keep their prior interpretation and block Save; grouping variants, currency placement, calendar keyboard input, milliseconds and explicit DST occurrences are covered by regression checks.
- Destination-specific loading frames retain actual table columns/control slots/page size, form groups and dialog boundaries. Unknown counts/empty states wait for responses; background refresh retains contents. Lazy Settings loading no longer shifts Dashboard layout.
- Form-designer group creation retains Unassigned drafts/settings; hidden incompatible connections can be revealed for explicit removal. Layout changes do not remove stored fields or links.
- Narrow/scrollable settings, Type/Status editors, user forms, command dialogs and relationship pickers preserve controls, rounded corners and space for actions; long labels wrap without widening their containers.
- User editing opens from rows or accessible name buttons, retains dirty baseline versions across refetches and resolves conflicts through Reset. Successful group save closes and returns focus. Dashboard search supports the common keyboard shortcut.
- Record return navigation retains list filters/focus or a validated linked source, rejecting unrelated destinations. Clickable rows respect embedded controls/text selection, keep the standard cursor and do not underline Keywords on hover. Not-found views use appropriate navigation icons and distinguish connection errors.
- Record/definition journals distinguish historical identities from reused technical names; empty/classification-only records retain creation history and historical usage still blocks unsafe definition deletion. Contact acceptance uses separate Contact-person records connected by Identities, never multiple Organizations for one Contact person.
- Local builds retain lazy assets for open clients, report chunk-load failures accurately and retain clean CI builds. PostgreSQL readiness uses TCP checks to avoid premature initialization success.
- Standard Base UI component composition, keyboard-help framing, theme-menu dismissal, creation icons, field focus/error states and unsaved-edit protection are consistent across the application.
