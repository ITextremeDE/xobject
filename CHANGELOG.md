# Changelog

All notable changes to xObject are documented here, using [Keep a Changelog](https://keepachangelog.com/en/1.1.0/). Software releases will use [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

The project is in early development. These entries describe source changes, including locally verified work that has not yet been published. No installable software release is available. Planned capabilities are identified as specifications rather than delivered functionality. Related changes within this unreleased baseline are consolidated to describe their final behavior; superseded intermediate UI states are not separate release features.

### Added

- Insert timestamp in multiline fields using the current user and effective regional time zone/format, preserving the cursor position and continuing on the next line; length-safe insertion and Markdown preview line breaks.
- Structured contact fields: ordered name components, multiple emails/phones/postal addresses/websites and birthdays with optional year and a compact regional text/calendar input; finite schema inventory through shared API/MCP, typed shadcn controls, whole-field permissions, safe conversions and atomic per-field journals with entry/path/order details.
- Base Contacts & Relations activation provisions protected Contacts and Distribution lists, fixed Contact-kind identities, permission-aware derived names, one Organization per Contact person, direct Identities and explicit distribution membership. Contacts reuse existing supplied Projects bindings. Bilingual fictional fixtures use the current profiles; relationship-role attributes and complete module delivery remain pending.
- Translated field descriptions/input hints, typed creation-only defaults and scalar uniqueness through the common field/classification editors and API/MCP rules. Defaults respect omission, conditions and creation rights; uniqueness includes recycled values and concurrent writes, with clear duplicate feedback. Record forms/previews use the same localized metadata and typed controls.
- Transactional business-number configuration per object: prefix/suffix, exact start/increment, padding and never/yearly/monthly periods in the workspace zone. Protected immutable numbers, append-only issuance, retained counters and atomic creation/journal rollback; number display/search in record and workspace lists. Current installation and bilingual fictional fixtures include both features.
- Workspace record recycle bin with shared searchable/filterable tables, read-only contents/Journal inspection, confirmed Delete-level recycling and Full-level restoration through UI/API/MCP. Normal reads/search/counts/selectors exclude recycled identities; fields, policies, edges and history remain retained. Lifecycle writes are versioned and atomic, retained links reserve cardinalities, and unavailable Primary associations do not expose parent contents. Permanent deletion/history erasure remain future work.
- Access principals can be placed, reordered and sized half/full in the Form designer using their existing protected field identity; sensitive demo forms start with the field in General.
- Access principals in record forms now use a searchable quick-selection field with tabbed rights details. Apply edits the form draft; record Save atomically persists contents, links and security with one version/change ID. Existing grades, public confirmation, reset/dirty guards and Full access checks remain enforced.
- One current unreleased installation definition and initial module catalog, schema/catalog fingerprint checks, empty initialization and guarded local reset. Authentication uses the pinned Better Auth schema API. Runtime/operator roles remain separate.
- Record-header “Link with…” and “New linked record” object dropdowns (only the supplied Organization/Contact-person assignment is omitted; General, Identities and other associations remain available): General-only direct actions, submenus using existing relationship side labels, an object-filtered existing-record picker and atomic linked creation through API/MCP. New records retain source context, inverse-side selection and guarded source return; versions, rights, conditions and cardinalities are enforced without replacing existing source links.
- Graded Access-principal ownership and separate Create rights, nested/graded groups, default/per-object foreign access in both directions, transitive bounded paths, optional own-record delegation and immediate inheritance/revocation controls. Record security includes workspace-public access with confirmation, Personal/Confidential privacy, foreign maxima, field exceptions and effective-right explanations; duplication respects visibility and creation validation. Shared API/MCP authorization protects searches/counts, Dashboard, relationships and history. Versioned editors and atomic journals use the current shared policy store; calendar-only operations and notification delivery remain future work.
- Object/field administrative ceilings for users and groups, additive active-group grants, explicit user overrides and installation-wide Administrator access. Sensitive types retain protected Access principals with creator defaults; membership and relationship links confer no content rights.
- Database-backed Modules settings with Contacts & Relations, Projects & Tasks and Documents & Communication. Projects activation supplies protected base Contacts/Projects/Cases/Tasks and fixed Contact → Project → Case UUID roles; planned modules remain visible. Reserved module object technical names apply even while modules are disabled/planned, and collisions never silently adopt custom definitions. Complete domain templates/shared-module ownership remain open.
- Form designer for actual workspace objects, with translated editable groups, scalar/relationship placement and ordering, half/full widths, optional relationship visibility and initial table state. New objects start with General; added elements remain Unassigned, including after group deletion. Versions, required-element guards, retained inactive entries preserve authored layouts and stored values. Module-specific metadata is retained without speculative UI views.
- Shared record and workspace tables with standard-only initial columns, account/view-scoped column visibility, current-page selection, supported server sorting/filtering, row actions and complete pagination. Dashboard combines the normal mixed-object table with exploratory real statistics/activity, shadcn dashboard-01 cards/gradients and a zone-aware 7/30/90-day chart. Growing management tables reuse the footer and muted headers.
- Read-only Projects-owned Primary hierarchy tree with inherited ancestor context, lazy paginated descendants, keyboard navigation, defensive cycle termination and explicit depth/context limits. General/custom connections remain in the Dossier.
- Relationship types with one object pair per custom definition, directed/undirected semantics, translated side labels, one conventional cardinality and separate required-link settings. Shared API/MCP validates composite workspace identities, protected system meanings, used pair/direction locks, activation preflight and atomic per-property journals. General stays core; Projects gates Primary association.
- Record-edge storage and identity registry with atomic scalar/relationship replacement, optimistic endpoint/definition versions, final-state cardinalities, Primary uniqueness/cycles and one central edge journal event projected to both endpoints.
- Generic field and relationship-endpoint applicability using stable unconditional single-choice controller/option UUIDs. Final-state validation, conditional requiredness and dependency protection retain incompatible data until explicitly cleared. The fictional Contact configuration supports one Organization per Contact person and direct symmetric Identities lists without another object type or name-based behavior.
- Full-width dedicated record creation/edit pages with one grouped form, sticky Save/Create/Reset actions, missing-field feedback, retained drafts across tabs and formatted previews/inactive-value disclosures. Created/changed metadata appears above Journal; technical details retain identities/version. Custom single-target connections use labeled InputGroups; multi-target sides use individual collapsible tables. General and subordinate Primary links are not duplicated in Details.
- Dossier data table with relationship type, object type, Keyword, Type, Status and Category; object filtering, localized search/sort, columns, page selection/actions and pagination. Record/definition/instance Journals share tables and structured detail dialogs, preserving immutable snapshots, current-name context, historical type formatting and the appropriate server/client pagination contract.
- Deferred business-row/registry integrity, definition versions, restricted runtime versus operator credentials, schema/workspace lock barriers, targeted graph checks and pagination/history indexes. Fresh-database guidance separates current initialization, Administrator provisioning and optional seeding.
- Explicit fictional ITextreme development seed with one account per role, English contents/default language, German/English metadata, all 15 custom field types, nine active objects with 74 records, an inactive lifecycle sample and 54 actual relationships. Forms, ownership, foreign access and field restrictions use normal operations; seeding refuses existing workspaces and keeps generated credentials private, separate from installation defaults.
- Administrator user management with start-password provisioning, mandatory first password change, optimistic edits, reversible activation and session revocation. Secret-free user/security journals are atomic; Workspace General shows creator and evidenced creation time. Instance Journal exposes recorded events with scope/property/entity-kind filtering.
- Workspace-scoped User/Designer roles and direct user groups with versioned membership/activation journals. Administrators manage roles/memberships and content grants; Designers configure permitted workspace definitions and input aids. Removing workspace access revokes direct memberships/grants without deleting accounts or history.
- Workspace language catalog/policy for shipped German/English packs, independent definition languages, retained unavailable preferences/translations, versioned API/MCP configuration and transactional journals. A shared translation input switches languages without losing draft labels.
- Named workspace time zones, optional personal overrides and regional display preferences independent of UI language. Exact numeric/money strings, date-only values, currency placement, first weekday, DST-gap rejection and explicit overlap selection are shared across record inputs, tables and journals.
- Shared workspace shadcn appearance: base/accent/chart palettes, primary/secondary overrides, radii, interface/heading fonts from the pinned 26-font catalog, menu surfaces/accents and interactive light/dark previews. Fonts/licenses are served locally; saved tokens cover portals and switching workspaces. Browser light/dark/system preference remains personal.
- Personal Profile, Account & security, Appearance and Language & region settings: own display-name changes, read-only sign-in email, verified password changes, own-session inspection/revocation, bounded failed-password guard and secret-free atomic journals. Avatar initials/disabled upload preparation does not enable image storage or email changes.
- Definition deactivation/reactivation and confirmed deletion only when unused, with dependency/current/history checks, protected supplied definitions, tombstones and atomic journals. Type/Status lifecycle is coupled; inactive content remains inspectable. Record recycling/restoration is implemented under ADR 0029; permanent deletion remains pending.
- Optional Keyword, Type/Status and Category installation through their shared editors and API/MCP, including required flags, stable localized choices/defaults, Without Type statuses, manual option ordering and single/multiple Category selection. Staged configuration and storage creation commit together; absent fields remain absent until explicitly installed and missing Keyword uses the UUID.
- Unified custom-field editor for Text, Multiline/Markdown, Integer, Decimal, Money, Boolean, Date, Date/time, choices, Email, international Telephone, URL and User/Group references. Requiredness, precise validation and lossless conversion preflight apply through all channels; conversion journals preserve original history.
- React/Vite frontend, shared TypeScript contracts and direct workspace/list/record/settings routes, URL search/sort/page state, guarded navigation, centralized keyboard shortcuts/help and scrollable Command/Ctrl+K navigation with authorized record search. Sidebar resources link to planned documentation/changelog/roadmap destinations above the user menu.
- Fastify/Kysely/PostgreSQL/Better Auth local backend with UUIDv7 identities, readable workspace-prefixed tables, localized definition labels, explicit initialization/provisioning commands, per-field journals, isolated PostgreSQL/web tests and GitHub application checks.
- Independent public Astro project introduction with Tailwind, ITextreme semantic tokens, selected Base UI shadcn primitives, self-hosted fonts, unchanged official brand assets, light/dark/system menus, validated MDX, metadata/sitemap and responsive/CSP browser checks. Full Starlight docs and product installation remain planned.

### Changed

- Specified additional contact-profile scope for professional position/function/department, nickname, communication languages, messaging, contact time zone, Wedding anniversary and optional Date of death (unknown year supported), with Photo/Logo preparation only; implementation and exchange remain pending.
- Distribution lists use General with Keyword and a short plain-text description, separate final Markdown Notes and no default business numbering; the demo description has three lines.
- Supplied long-form notes and demo narratives use Markdown; English fictional examples include domain-specific sections, action lists and sample timestamped notes.
- Markdown preview and read-only text share explicit heading/list/quote/link/code typography, preserving line breaks and omitting raw HTML and images.
- Custom-object starter forms and demo layouts share editable General, separate Primary association before Classification, list-only Relationships and final Notes groups when the corresponding elements exist; later additions remain explicitly Unassigned. Maximum-one links start in General. Existing authored layouts retain their grouping and order.
- Contacts select Organization, Contact person or Individual contact before creation and retain that kind through UI/API/MCP updates. Fixed contact cores put names/Organization first, omit derived-name/controller inputs and use compact contact rows and always-visible name details and expandable address details. Salutation and Academic title are independent configurable selects; personal-name fields follow the agreed order in Name & organization without an additional-name disclosure. Further details sits alongside it on large screens and contains Business number, birthday, optional configurable Gender (separate from Salutation) and applicable register information; Contact details and Addresses share a second row with consistent section headings, including Notes. Contact details lists telephone numbers before email addresses and websites. Telephone rows and field input aids separate configurable Usage and Phone type, each with an optional single selection and stable option-group metadata; usage, type and number align in one row in wide containers and wrap on smaller screens. Collection headings have compact Add actions; rows expose configurable labels and direct reorder buttons. Order determines preference consistently through UI/API/MCP; independent preference controls are removed. Invalid draft entries no longer mark correct siblings invalid. Contact rows use consistent visible labels and give the telephone number more width; preference help is compact and expandable. Unframed address entries use separators between addresses and group their label/actions above the postal fields; Region/state appears before Country in the main address fields; formatted-address text is omitted from manual input. Business number appears only in Further details; loading uses the same responsive composition. First/last names use one plain text input each, without component-list controls; untouched structured names retain their values and identities. The Form designer shows the protected core and configures additional fields/custom relationships; field input aids remain editable.
- Specified the staged structured-domain architecture in ADR 0032: typed JSONB codecs, shared object/relationship field metadata, purpose bindings, retained-reference integrity, whole-field and both-endpoint rights, field-level history, domain-zone values and sparse versioned recurrence overrides. Defined API/MCP/UI integration and staged acceptance; the contact-field/base-provisioning slice is implemented, while role attributes, temporal codecs, recurrence and synchronization remain pending.
- Elaborated draft start profiles for all 22 V1 objects, with bilingual field recipes, initial forms/input aids, 16 explicit relationship proposals and per-profile acceptance. Separated standards-aligned structured values from lean scalar templates, identified storage/edge-attribute/exchange prerequisites and retained current implementation and later synchronization boundaries.
- Defined lean starting templates for V1 objects outside the five standards-aligned groupware profiles: essential fields/relationships, configurable input aids and editable forms, with authorized extensions instead of speculative specialist workflows. Existing domain decisions, module protection and configuration-role boundaries remain unchanged.
- Specified vendor-neutral groupware model alignment for Contacts, Distribution lists, Appointments, Vacations and Tasks: vCard/iCalendar profiles, complementary JSContact/JSCalendar references, explicit mappings and future CardDAV/CalDAV boundaries. Includes repeated contacts, partial birthdays, date/time/recurrence semantics and loss-aware interoperability; no synchronization or calendar delivery claim.
- Reconciled documentation against source and accepted product decisions: corrected obsolete storage tables/column order, recycle-bin and inherited-rights status, business-number search/columns and module scope; linked ADR refinements and consolidated guidance/release entries. Local implementation, target behavior and publication remain distinct.
- Specified Contacts & Relations and Projects & Tasks as the two V1 modules with a 22-object shared catalog, preserved existing requirement IDs, defined the outstanding domain-profile specification process and clarified shared-module activation/evolution acceptance. Documents & Communication and the other target modules remain later scope; catalog decisions do not claim implemented templates or specialized accounting/messaging functions.
- Unified field labels/descriptions/hints and direct control associations, clear field-editor sections with collapsible help, stacked mobile translations and compact expandable numbering settings. Business numbers use consistent standard columns and permitted global-search labels. Validation identifies/focuses the affected field or uniqueness rule. Group editors include graded memberships with atomic name/member Save and shared Reset; user administration explicitly labels instance roles.
- Consolidated graded ownership in one policy store; Access principals are virtual. Supplied-object bindings also provide the fixed Primary roles. Current API/MCP operations replace parallel journal, ungraded-membership, requiredness and language-only interfaces.
- Development initialization rebuilds the current model without preserving obsolete development schemas or fixtures. Application builds clear generated output; current integration tests replace upgrade-only scenarios.
- Permission administration explains effective user/group sources, separates principal lists from grants, exposes direct selection actions and keeps Save/Reset in the fixed footer. Object labels and sensitivity save atomically with both expected versions; member removal explains grant/membership effects before confirmation.
- Settings and nested editors use the Sidebar 13 background hierarchy and consistent rounded functional sections, spacing, responsive tables and fixed action placement. Record groups/loading states reuse these sections and full main-content width. Personal/workspace/instance navigation shares one ordered definition; email belongs to Account & security.
- Object/field administration separates properties, alphabetical fields, lifecycle/history and framed technical details. Consistent Yes/No requiredness, shared translation controls, staged optional standards and side-by-side Type/Status input aids retain Save/Reset and dependency protection.
- Relationship editors start with object pair/direction, then identity and applicable side controls. Symmetric sides share controls; independent drafts survive mode changes. Fixed values use read-only presentation, and technical-name controls share format/fixed-name help. New definitions clearly start as drafts.
- Record/table menus use consistent icons, spacing and copy-ID grouping; Dashboard “Add filter” adds object-filter tabs. User-menu/resource spacing, toolbar alignment, responsive period selection and gradient chart presentation follow the selected shadcn examples while retaining actual authorized data.
- Common dialog actions use Cancel/Create for creation, Close/Reset/Save for editing and explicit destructive confirmations. Reset supports invalid drafts; normal dialogs have localized close buttons and all close paths preserve pending/dirty guards.
- Standard-field names/technical names are reserved even when absent; unused Type/Status options can be deleted only without current/history references or retained child mappings. Deleted identities are never reused. Administrator status uses the protected `sys_users.is_admin` flag.
- Public website header/footer use the shared ITextreme structure, neutral theme/mobile icon menus, semantic surfaces, compact navigation, nine social icons and actual stack/developer credit, retaining CSP and asset notices.

### Fixed

- Record and instance journals format structured historical values with their historical field definitions. - Virtual Access principals remain displayable without unsupported sorting; invalid list-sort URLs recover automatically. Protected system-field inspection avoids false reserved-name/role warnings, and creation restrictions no longer mislabel active object types as inactive. Security journals use translated properties/rights and current principal names while retaining original snapshots. Recycle-bin previews share form groups, widths and dialog actions, separate inactive fields and respect applicability/field visibility; Command-K includes the workspace recycle bin.

- Permission administration retains inactive policy entries, rejects new inactive memberships/foreign rules, preserves deleted-object overrides without blocking edits, journals removed Create grants and reports per-record field ceilings. Rights editors retain draft versions, distinguish default rules from object overrides, show effective Create/current access, and share clear translated sections, pagination, save shortcuts and guarded read-only/pending states.
